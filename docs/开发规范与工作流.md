当前处于“工程化迁移期”：

- 主进程由 `main.js` 负责启动编排，窗口/托盘/隐私选择器已拆到 `app-shell.js`，所有 IPC handler 已拆到 `src/main/ipc/*.ipc.js`
- `main.js` 中不再保留任何内联 IPC handler
- preload 已成为 renderer 调用 Electron 能力的默认入口
- 新功能优先落在新边界，不再继续扩大 renderer 直接访问 Electron 的旧模式

## 3. 日常开发命令

```bash
npm start
npm run lint
npm test
npm run verify
npm run build
npm run build:zip
```

约定：

- `npm start`：本地开发启动
- `npm run lint`：当前等价于项目自定义结构校验脚本
- `npm test`：最小单元测试
- `npm run verify`：提交前必须通过，等价于 `lint + test`
- `npm run build`：生成安装包
- `npm run build:zip`：生成 ZIP 发布产物

开发版启动注意事项：

- `npm run dev` / `npm start` 会启动 Electron GUI，必须在真实桌面权限下验证。Codex、CI 或受限 shell 中直接启动 GUI 时，可能出现 Chromium GPU 子进程失败，不能据此直接判断业务代码损坏。
- `npm run dev` 必须跟随 `src/` 目录源码修改自动重启 Electron 子进程，覆盖 main、preload、renderer、CSS 和 HTML。该能力由 `scripts/start-electron.js` 的父进程 watcher 提供；日志应出现 `[start-electron] watching ...`，源码文件修改时间变化后应出现 `source changed ... restarting Electron...`。watcher 必须过滤目录噪声、临时文件和无 mtime 变化事件，避免开发版无源码保存时自我重启。只有排查 watcher 本身时才允许临时设置 `NEKO_DISABLE_DEV_WATCH=1`。
- 如果日志出现 `GPU process exited unexpectedly` 或 `GPU process isn't usable. Goodbye.`，先用 GUI 权限重跑 dev；仍失败时再临时执行 `npm run build`，启动 `dist/win-unpacked/NekoStatus.exe` 对照。
- 正式 exe 能打开、dev 只在受限启动环境失败时，优先排查 `scripts/start-electron.js`、Electron dev binary、GPU fallback、透明/无边框窗口等启动链路。
- `scripts/start-electron.js` 默认不禁用硬件加速；只有捕获 GPU fatal 后才自动以软件渲染兜底重试，人工强制兜底可设置 `NEKO_DISABLE_HW_ACCEL=1`。

条件型 UIUX 的开发版场景命令：

```bash
npm run dev:startup-update:checking
npm run dev:startup-update:available
npm run dev:startup-update:download
npm run dev:startup-update:installing
npm run dev:startup-update:failed
npm run dev:startup-update:offline
npm run dev:startup-update:up-to-date
```

这些命令用于复现启动前自动更新窗口的检查、发现更新、下载进度、安装交接、失败放行、离线放行和已是最新状态。新增只能在特定条件下出现的 UI 时，必须同步提供类似的开发版触发方式，避免后续只能靠真实网络、真实发布包或临时改代码验证。

## 4. 开发边界

### 主进程

- `src/main/main.js` 负责启动编排、生命周期、自动更新调度和版本比较工具
- `src/main/app-shell.js` 负责窗口、托盘、初始状态同步与隐私窗口选择器
- `src/main/ipc/*.ipc.js` 负责各领域 IPC handler；新增主进程 IPC 时优先放到这里
- 与系统交互的纯能力尽量放进 `system-utils.js`
- 配置默认值和兼容逻辑统一维护在 `config-store.helpers.js`
- 复杂 IPC payload 优先走 `src/shared/schemas.js`

### Preload

- Electron 能力只通过 preload 暴露给 renderer
- `src/preload/index.js` 是主页面入口
- `src/preload/privacy-picker.js` 只给隐私选择器使用
- renderer 不再新增 `require('electron')` 直连实现

### Renderer

- `app.js` 负责 renderer bootstrap 元信息
- `app-ipc.js` 负责兼容启动 `core/app-runtime.js`
- `core/app-runtime.js` 负责 renderer services、pages、components 与主进程事件 runtime 的装配
- 新增页面逻辑时，优先按 `pages / services / state / components` 方向拆分
- 新增 DOM 状态、事件绑定、输入解析和页面渲染逻辑不得继续写入 `app-ipc.js`；跨模块装配和依赖注入放入 `core/app-runtime.js`，主进程事件转发放入 `core/app-event-runtime.js`

### Shared

- `src/shared/ipc-contracts.js` 维护 invoke channel 与 event 常量
- `src/shared/schemas.js` 维护跨层 payload 校验

## 5. 验证要求

提交前至少完成：

1. `npm run verify`
2. 与改动相关的手工 smoke test
3. 如改动涉及打包、更新、托盘、截图、推流等系统行为，再额外跑一次 `npm run build` 或 `npm run build:zip`
4. 如 dev 启动异常，必须记录 `npm run dev` 日志、`npm run build`/临时 exe 对照结果，以及是否使用真实 GUI 权限启动

测试约束不能为了让当前改动通过而被擅自放宽。删除断言、跳过失败用例、扩大 mock、降低 schema 校验或把失败路径改成成功路径，都必须有明确产品契约变化、对应实现修改和文档说明。

## 6. CI 约束

- `ci.yml`：运行 `npm run verify`
- `build-check.yml`：Windows 环境运行 `npm run verify` 与完整 `npm run build`
- `release.yml`：发布前同样执行 `npm run verify`

## 7. 功能改动原则

- 改功能前先判断是否需要新增 IPC
- 改配置前先补默认值与兼容迁移
- 改 renderer 前先判断是否应该抽成页面、状态或服务
- 改更新逻辑前同步检查 [RELEASE_WORKFLOW.md](/D:/VScode%20project/Neko_Status/docs/RELEASE_WORKFLOW.md)
- 改 IPC 时同步检查 [ipc-contract.md](/D:/VScode%20project/Neko_Status/docs/ipc-contract.md)

## 8. 文档同步要求

出现以下情况时必须更新文档：

- 新增或废弃 IPC
- 新增 preload 能力
- 新增配置项
- 修改窗口、托盘、更新、截图、推流等关键系统行为
- 修改开发命令、测试命令或打包命令

优先同步：

- 本文
- 对应专题文档
- `CONTRIBUTING.md`
