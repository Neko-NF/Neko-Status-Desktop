# 功能生命周期规范

## 新增功能

1. 先创建 issue，写清目标和验收标准。
2. 判断是否需要新增 IPC。
3. 判断是否需要新增配置项。
4. 判断是否需要新增页面、组件或系统权限。
5. 实现代码。
6. 补测试。
7. 补文档。
8. 提 PR。

## 修改功能

1. 明确是行为变化还是纯重构。
2. 行为变化必须更新测试和文档。
3. 涉及 IPC 变化时，优先保持兼容，或明确迁移说明。

## 删除功能

1. 确认是否仍有入口、配置、IPC、定时任务依赖。
2. 先移除页面入口。
3. 再移除 IPC、配置和任务。
4. 删除或更新对应测试。
5. 更新文档与发布说明。

## 新增 UI 页面

1. 明确页面属于独立页面还是已有页面的子区块。
2. 优先放在 renderer 的页面化方向中。
3. 不新增直接访问 Electron 的实现。

## 新增后台服务

1. 明确服务属于已有 service 还是需要新文件。
2. 明确配置来源、日志出口、IPC 调用入口。
3. 增加最小可验证路径。

## 新增系统权限能力

1. 明确平台限制。
2. 提供失败回退路径。
3. 在文档中写清楚验证方式。

## 文档同步

以下任一变化都必须补文档：

- IPC
- 配置项
- 页面结构
- 测试命令
- 发布流程
