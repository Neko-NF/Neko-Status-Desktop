# UIUX 文案与排版规范

> 适用范围：Electron 桌面端当前版本及后续新增页面。  
> 最后更新：2026-05-19

## 1. 目标

本规范补齐团队在界面文案、文本层级、按钮触达、昼夜主题适配上的统一标准。任何新增或重构 UI，除了遵守 `frontend-guideline.md` 的工程分层，也必须同步检查本文。

## 2. 文案层级

界面文案按信息优先级分层，不允许所有文字使用同一字号或同一权重。

| 层级 | 使用场景 | 推荐字号 | 字重 | 要求 |
| --- | --- | --- | --- | --- |
| 页面标题 | 页面主标题、弹窗主标题 | 20-24px | 600-700 | 一屏只保留一个最高层级标题 |
| 区块标题 | 卡片标题、设置分组标题 | 16-18px | 600-700 | 必须能在扫视时定位功能区域 |
| 行标题 | 表单项名、列表主文案、卡片核心字段 | 14-16px | 500-700 | 不低于 14px |
| 正文说明 | 解释、提示、次要状态 | 13-14px | 400-500 | 行高不低于 1.55 |
| 辅助标签 | 时间、短标签、单位 | 12-13px | 500-700 | 仅用于短文本，不承载关键决策信息 |

关键状态、版本号、速度、延迟、仓库名、风险提示等决策信息不得低于 13px；需要用户立即判断的值应使用 `font-weight: 700` 或语义色突出。

## 3. 文本排版

- 中文界面优先使用短句，避免在按钮、标签和表头里塞入解释性长句。
- 一个操作按钮只表达一个动作，例如“保存更新源”“确认删除”，不要写成“点击这里保存当前更新源”。
- 列表或卡片内同类字段必须对齐。推荐使用两列结构：左侧标签，右侧值；长值必须支持省略并提供 `title`。
- 同一个页面内的状态词必须一致，例如“待检测 / 检测中 / 已检测 / 检测失败”不能混用近义词。
- 危险操作必须出现明确对象和后果，例如“删除此更新源？删除后将自动切换到下一个可用源。”

## 4. 按钮与触达尺寸

- 常规文本按钮最小高度 40px；高频或底部主操作最小高度 44px。
- 图标按钮若独立承担操作，最小触达区域为 36x36px；危险或修改类操作建议使用“图标 + 文本”，最小高度 40px。
- 轮播、分页、左右切换等方向按钮最小触达区域为 40x56px，并需要有清晰 hover/focus 状态。
- 删除、覆盖、重置等危险操作必须有二次确认；确认层文字不低于 13px，确认按钮不低于 44px。

## 5. 昼夜主题适配

- 新样式必须使用 `tokens.css` 中的变量，不直接写死浅色背景或深色背景。
- 卡片背景优先使用 `--surface-raised` / `--surface-raised-hover`，边框使用 `--border-color`。
- 语义色使用 `--success-mint`、`--warning-amber`、`--error-coral`、`--theme-color`。
- 任何新增半透明背景都必须在浅色和深色模式下检查对比度，尤其是绿色成功态、红色危险态和蓝色主题态。
- 不允许只在暗色模式下看起来正常；浅色模式下文字、边框、按钮 hover 必须仍可辨认。

## 6. 卡片布局

- 卡片必须有清晰的信息结构：标题区、核心信息区、状态或元信息区、操作区。
- 不允许在卡片底部留下大块无意义空白。若内容较少，应补充有价值的元信息、状态摘要或收紧高度。
- 卡片内操作区应固定在视觉末端，并与内容保持 8-12px 间距。
- 关键字段不能只依赖颜色表达，需要同时有文字标签或图标辅助。
- 同一行内的主卡片和辅助卡片必须视觉对齐：顶部基线一致，高度差不得超过 8px；若一侧包含分页点、按钮或说明文字，另一侧也要以等高容器或内部留白保持视觉平衡。
- 卡片内字段推荐使用“标签 + 值”的对齐结构。标签左对齐，值在同一列内对齐；长值使用省略号，但不得压缩按钮或状态徽章。
- 主信息区、元信息区和操作区之间保持稳定间距，避免一侧内容贴边、另一侧内容松散。常规卡片内边距建议 16-20px。

## 7. 堆叠式卡片与轮播

- 堆叠式轮播必须同时满足“层次可见”和“当前项可读”：当前卡片完整显示，下一张卡片只作为背景层露出，不承载必须阅读的信息。
- 当前卡片可响应 hover/focus 动画，背景层不得抢占点击；左右切换按钮和分页点是主要导航方式。
- 侧卡可以显示低强调摘要内容，例如序号、标题、服务器和仓库路径；但不得显示可点击的主操作按钮，也不得让侧卡内容的权重高于当前卡。
- 侧卡内容必须来自该卡自身数据，不能镜像或克隆当前卡的序号、标题、状态或操作文案。
- hover 动画不得让卡片超出可视容器被裁剪；优先使用阴影、描边、轻微缩放，谨慎使用向上位移。
- 需要参考银行卡式/陈列式轮播时，应使用 perspective、translateZ、rotateY、scale 形成左右卡片退后的空间关系；当前卡片必须拥有更高 z-index 和更实的背景，避免侧卡文字穿透当前卡。
- 左右侧卡片可以点击切换，但侧卡上的按钮、表单等细节不得成为主要操作入口；主要操作只放在当前卡。
- 有顺序含义的卡片轮播必须从 1 开始标注序号。序号应放在扫视时能立即看到的位置，当前卡显示自身序号，侧卡至少露出相邻卡序号，帮助用户理解切换方向。
- 若真实卡片不足三张，应按缺口补齐占位槽。占位槽参与编号、分页点和左右切换，视觉与真实卡一致，并展示示例服务器、仓库路径和引导文案。
- 占位槽可以被选中并引导用户填写；保存新更新源时应优先替换当前或最靠前的占位槽。占位槽不得作为真实更新源参与检测或写入 `activeUpdateSourceId`，也不得提供删除操作。
- 卡片内有醒目序号时，修改、删除等操作按钮应避开序号所在角落，优先放在对侧或底部对齐区，避免点击目标与装饰数字重叠。
- 删除等二次确认可以使用 3D 翻面，但外层轮播位移和内层翻面必须分层实现：外层负责 position/transform，内层负责 rotateY，防止动画互相覆盖。
- 堆叠层级建议不超过三层。第二层透明度可低于当前卡，但文字不能误导为当前可操作内容。
- 轮播卡片的高度应与同一行的状态卡、详情卡保持一致；分页点计入整体卡片组高度。
- 切换动画只能改变 transform、opacity、filter 等低成本属性，不得引发布局跳动。

## 8. 评审清单

提交前检查：

- 昼夜主题都已查看，文字、边框、背景没有失焦或糊成一片。
- 页面主操作、危险操作、左右切换按钮满足最小触达尺寸。
- 关键文字不低于 13px，卡片标题不低于 16px。
- 文案对象明确，危险操作有二次确认和后果说明。
- 长文本不会撑破布局，省略文本有 `title` 或等效可发现方式。
- 同一行卡片的顶部、底部和操作区在视觉上对齐，没有一侧明显短、一侧明显长。
- 堆叠式轮播的背景层不会遮挡当前卡片，不会抢占点击。
- 新增 UI 已落在正确 CSS 分层，不把页面专属样式写入 `main.css`。

## 9. 创新组件准入

允许个人或小组为新功能设计新的局部组件，例如自绘日期选择、状态摘要条、紧凑筛选器、诊断时间线等。准入标准：

- 必须能解释它解决了什么用户问题，而不是单纯为了“更炫”。
- 必须提供明确状态：默认、hover、focus、active、disabled、loading、error。
- 必须跟随主题变量，主视觉色优先使用 `--theme-color`，语义反馈使用项目语义色。
- 必须避免廉价感：不使用多色渐变进度条、大面积扫光、跳动装饰、无意义浮动元素。
- 必须有复用命名，页面专属类名使用页面前缀；跨页面组件使用稳定组件类名。
- 必须在浅色、深色、缩放和窄窗口下检查文字不重叠、不溢出、不遮挡操作。

错误或失败类提示不应只放在列表空态里。刷新失败、保存失败、接口异常、权限不足等需要用户立即知道的状态，应同时使用页面内状态和灵动岛/弹窗等醒目反馈。

### 下拉控件文案与布局

- 下拉项使用短词，不写解释性长句；需要解释时放在旁边说明或选中后的详情区。
- 当前选中值必须一眼可见，不只依赖颜色或图标。
- 选项图标只做辅助识别，文字仍是主要信息。
- 下拉按钮内文字必须单行省略，不允许被压成竖排或挤压相邻按钮。
- 短选项下拉的触达高度不低于 40px，菜单项不低于 36px。

## 数据表与管理页面

后台管理类页面应优先服务“快速扫描、比较、操作”，不要做成营销式展示页：

- 页面只保留一个最高层级标题。若顶部导航或面包屑已经显示当前页面名称，内容区不要重复同级标题，可改为辅助说明、筛选条件或统计摘要。
- 筛选控件、刷新、创建等主操作应组成同一条工具栏，按钮之间保持 8-12px 间距，工具栏与下方表格/表单保持 20-24px 间距。
- 数据表列必须视觉对齐。表头、单元格、状态、操作按钮应共享稳定列宽；推荐为固定列数的数据表设置 `colgroup`。
- 操作列应放在最右侧，宽度固定，按钮右对齐。编辑/删除等同行操作可以横排，但必须有稳定 `gap`，不得贴边或换行挤压。
- 状态列不得只依赖颜色。至少保留“生效中 / 已下线 / 待处理”等文字，必要时再配语义色或图标。
- 长文本只在主内容列省略，操作列、状态列、时间列不得被长文本挤压。省略内容必须提供 `title` 或其他可发现的完整文本入口。
- 表格 hover 只允许改变背景、边框或阴影，不得使用会造成列错位或行高变化的 `scale`、`translate`。
- 表单 footer 与表单主体之间应有清晰分隔和不低于 16px 的顶部间距，避免按钮贴近上一行控件。
