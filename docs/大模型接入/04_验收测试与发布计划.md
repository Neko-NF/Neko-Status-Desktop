# 04 — 大模型智能诊断助手验收测试与发布计划

> 状态：验收设计讨论稿  
> 目标：确保大模型能力不破坏现有核心链路

## 一、测试分层

| 范围 | 最低测试 |
| --- | --- |
| IPC constants / events | `tests/unit/ipc-contracts.test.js` |
| schema / payload 校验 | `tests/unit/schemas.test.js` |

## 二、关键测试用例

### 配置

- 默认 `llmConfig.enabled=false`。
- 保存 endpoint/model/timeout 后能读回。
- 保存 API Key 后，renderer 只能看到 `hasApiKey=true` 和掩码。
- 旧配置缺少 `llmConfig` 时能正常 merge。

### 脱敏

- 设备密钥、JWT、GitHub token、个人仓库 token、模型 key 全部被替换。
- URL query 和 hash 被移除。
- base64 长串被替换。
- 嵌套对象和数组中的敏感字段也被替换。

### 模型请求

- 未启用时返回 `LLM_DISABLED`。
- 缺少 endpoint/model/key 时返回 `LLM_CONFIG_MISSING`。
- endpoint 不可达时返回结构化错误。
- 401/403 映射为 `LLM_AUTH_FAILED`。
- 429 映射为 `LLM_RATE_LIMITED`，保留 retry-after 信息。
- 超时映射为 `LLM_TIMEOUT`。
- 非 JSON 响应映射为 `LLM_RESPONSE_INVALID` 或保留原始文本折叠展示。
- 并发请求返回 `LLM_REQUEST_IN_PROGRESS`。
- 取消请求返回 `LLM_REQUEST_CANCELLED`。

### UI

- 未配置时按钮展示明确状态，不假装可用。
- 点击诊断后先展示上下文预览。
- 用户取消后不发送请求。
- 请求中按钮禁用或展示加载态。
- 成功后展示结论、发现、建议、风险提醒。
- 失败后展示可恢复错误，不影响服务状态。

### 核心链路回归

- 上报服务启动/停止不受 LLM 配置影响。
- 截图开关、隐私规则、更新检查、开发者控制台已有命令不受影响。
- dev 日志没有 `preload bridge missing`、`No handler registered`、renderer 初始化错误。

## 三、验证命令

最低验证：

```bash
npm run verify
npm run test:smoke
```

涉及打包、安全存储或安装包回归时增加：

```bash
npm run build:zip
```

Windows 上若 `npm test` 并发出现资源错误，可按现有测试规范使用串行单测复核。

## 四、手工验收场景

1. 未启用智能诊断
   - 打开设备状态页。
   - 确认智能诊断入口展示未启用或引导配置。

2. 配置无效 endpoint
   - 配置一个不可访问 endpoint。
   - 点击测试连接。
   - 确认出现网络失败说明，服务上报仍正常。

3. 成功诊断
   - 配置有效 endpoint、model、key。
   - 点击智能诊断。
   - 检查上下文预览不含密钥。
   - 确认结果结构化展示。

4. 用户取消
   - 打开上下文预览。
   - 点击取消。
   - 确认没有发出模型请求。

5. 开发者控制台
   - 执行 `llm status`、`llm context`、`llm diagnose 为什么上报失败`。
   - 确认命令输出正常，且不暴露敏感字段。

## 五、发布策略

建议默认以实验功能发布：

- `llmConfig.enabled=false`。
- UI 明确标记为智能诊断。
- 首次启用展示隐私说明。
- release notes 标明需要用户自行配置模型服务或等待服务端代理。
- 若服务端代理尚未完成，文案不得暗示官方已经提供免费额度。

## 六、回滚方案

### 用户级关闭

- 关闭 `llmConfig.enabled`。
- 删除模型 API Key。
- 智能诊断入口回到未启用状态。

### 开发级回滚

- 保留配置字段但隐藏入口。
- 移除或禁用 `llm` 控制台命令。
- IPC handler 返回 `LLM_DISABLED`。

### 版本回退

- 旧版本缺少 `llmConfig` 时应忽略该字段。
- 新版本读取旧配置时自动 merge 默认值。
- 不引入破坏性配置迁移。
