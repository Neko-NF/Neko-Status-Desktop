# 03 — 大模型接入数据隐私与安全边界

> 状态：安全设计讨论稿  
> 原则：默认最小发送、发送前预览、敏感字段不可出端

## 一、核心原则

- 用户主动触发才允许发送上下文。
- 发送前必须展示脱敏后的上下文预览。
- 默认不发送截图、完整窗口标题、完整 URL、token 和密钥。
- 模型 API Key 不进入 renderer、不进入日志、不进入模型上下文。
- 模型回答只作为建议，不自动执行任何操作。
- 开发者控制台仍保持白名单命令模型。

## 二、数据分类

### 可默认发送

- 应用版本、平台、运行模式。
- 服务是否运行、最近一次上报是否成功。
- 连续失败次数、自动重启次数、健康检查摘要。
- CPU/内存/电池等数值型指标。
- 截图是否启用、是否跳过、跳过原因、压缩体积摘要。
- 更新源模式、源类型、最后错误码。
- 脱敏后的最近日志。

### 需用户显式允许

- 当前前台应用名称。
- 窗口标题摘要。
- 最近日志的更多行数。
- 服务器 URL 的域名部分。
- 用户手动输入的补充说明。

### MVP 禁止发送

- 截图原图、缩略图、base64。
- 设备密钥、API Key、JWT、GitHub token、个人仓库 token。
- 模型 API Key。
- 完整 URL query、授权头、cookie。
- 本地完整文件路径。
- 未脱敏的 shell、PowerShell、构建或联调输出。

## 三、脱敏规则

建议新增统一 `redactLlmContext(value)` helper，至少覆盖：

| 类型 | 处理方式 |
| --- | --- |
| `deviceKey`、`apiKey`、`authToken`、`githubToken`、`personalUpdateToken` | 替换为 `[REDACTED_SECRET]` |
| Bearer token | `Bearer [REDACTED_SECRET]` |
| `sk-...` 等模型 key | 保留前后 2~4 位，其余替换 |
| URL query | 删除 query 和 hash |
| Windows 用户目录 | 替换用户名段 |
| 可能的邮箱 | 局部掩码 |
| base64 长串 | 替换为 `[REDACTED_BLOB]` |

脱敏 helper 必须有单元测试，覆盖嵌套对象、数组、字符串日志和大小写变体。

## 四、密钥存储

MVP 要求：

- renderer 不保存明文模型 API Key。
- preload 不暴露读取明文 key 的方法。
- 设置页保存 key 时通过 IPC 交给主进程处理。
- 返回给 UI 的只有 `hasApiKey` 和掩码预览。
- 导出日志、开发者控制台和诊断上下文不得包含明文 key。

如果当前配置系统无法满足安全存储，应先实现安全字段存储，不能把模型 key 当普通配置明文写入。

## 五、请求安全

- endpoint 必须是 `https://`，本地开发可允许 `http://127.0.0.1` 和 `http://localhost`。
- 禁止 file、ftp、自定义协议。
- 禁止把用户输入拼接为 header 名、IPC channel 或 shell。
- 请求 header 由主进程固定生成。
- 超时默认 30 秒。
- 同时最多 1 个请求。
- 取消请求后必须清理 AbortController。

## 六、模型回答边界

模型回答不得直接触发：

- 修改配置。
- 删除文件或缓存。
- 开始/停止服务。
- 安装更新。
- 打开外部 URL。
- 执行命令。

如果未来做“应用建议”能力，必须改为二次确认流程：模型生成配置草案，用户逐项确认，主进程按已有配置 IPC 写入，并保留回滚。

## 七、日志与审计

本地日志可以记录：

- 请求开始/结束时间。
- provider 类型。
- model 名称。
- 请求耗时。
- 上下文字符数。
- 错误码。

本地日志不得记录：

- prompt 全文。
- 模型 API Key。
- 完整模型响应。
- 未脱敏的诊断上下文。

如后续接服务端代理，服务端也必须遵守相同脱敏和最小留存原则。
