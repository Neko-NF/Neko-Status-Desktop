# 02 — 大模型智能诊断助手开发方案与任务拆解

> 状态：开发设计讨论稿  
> 目标：为后续开发 agent 提供明确落点、契约和验收口径

## 一、架构原则

大模型能力按独立领域接入，遵守现有 Electron 分层：

```text
renderer page/component
  -> renderer service: src/renderer/js/services/llm-client.js
  -> preload: src/preload/index.js
  -> IPC contract/schema: src/shared/ipc-contracts.js, src/shared/schemas.js
  -> main ipc: src/main/ipc/llm.ipc.js
  -> main service: src/main/llm-service.js
  -> provider endpoint / future server proxy
```

不得把模型调用写入 `status-service.js` 的上报 tick，也不得让 renderer 直接请求模型 endpoint。

## 二、建议新增配置

在 `src/main/config-store.helpers.js` 增加默认值：

```js
llmConfig: {
  enabled: false,
  provider: 'custom-compatible',
  endpoint: '',
  model: '',
  apiKeyEncrypted: '',
  timeoutMs: 30000,
  maxContextChars: 16384,
  previewBeforeSend: true,
  includeWindowTitle: false,
  includeRecentLogs: true,
  includeUpdateDiagnostics: true,
}
```

说明：

- `previewBeforeSend` 在 MVP 必须保持 true。
- `apiKeyEncrypted` 应由主进程安全存储或加密后保存；renderer 不接触明文。
- 如果现有配置系统暂不支持安全字段，需要先补安全字段存储 helper。

## 三、建议新增 IPC

在 `src/shared/ipc-contracts.js` 增加：

```js
LLM_GET_CONFIG: 'llm:getConfig',
LLM_SAVE_CONFIG: 'llm:saveConfig',
LLM_TEST_CONNECTION: 'llm:testConnection',
LLM_BUILD_CONTEXT: 'llm:buildContext',
LLM_DIAGNOSE: 'llm:diagnose',
LLM_CANCEL: 'llm:cancel',
```

后续如需要流式输出，再增加事件：

```js
LLM_STREAM_DELTA: 'llm:streamDelta',
LLM_STREAM_DONE: 'llm:streamDone',
LLM_STREAM_ERROR: 'llm:streamError',
```

MVP 可以先不做流式输出，降低复杂度。

## 四、核心数据结构

### 4.1 LLM 配置

```js
{
  enabled: true,
  provider: 'custom-compatible',
  endpoint: 'https://example.com/v1/chat/completions',
  model: 'model-name',
  timeoutMs: 30000,
  maxContextChars: 16384,
  previewBeforeSend: true,
  includeWindowTitle: false,
  includeRecentLogs: true
```

```js
{
  hasApiKey: true,
```

## 五、主进程服务设计

新增 `src/main/llm-service.js`，职责：

- 读取和保存 LLM 配置。
- 安全处理 API Key。
- 构建诊断上下文。
- 执行脱敏和上下文裁剪。
- 调用 provider endpoint。
- 解析模型返回。
- 输出统一错误码。
- 控制并发、超时和取消。

建议错误码：

| code | 含义 |
| --- | --- |
| `LLM_DISABLED` | 未启用智能诊断 |
| `LLM_CONFIG_MISSING` | endpoint、model 或 key 缺失 |
| `LLM_CONTEXT_EMPTY` | 无可发送上下文 |
| `LLM_REQUEST_IN_PROGRESS` | 已有请求进行中 |
| `LLM_REQUEST_CANCELLED` | 用户取消 |
| `LLM_AUTH_FAILED` | 鉴权失败 |
| `LLM_RATE_LIMITED` | 被限流 |
| `LLM_TIMEOUT` | 请求超时 |
| `LLM_PROVIDER_ERROR` | 供应商返回错误 |
| `LLM_RESPONSE_INVALID` | 响应格式无法解析 |

## 六、renderer 设计

### 入口

MVP 推荐：

- 在设备状态页或服务页增加“智能诊断”按钮。
- 在设置页增加“大模型/智能诊断”配置区。
- 在开发者控制台增加 `llm` 命令组。

### UI 状态

必须覆盖：

- 未启用。
- 未配置。
- 正在构建上下文。
- 上下文预览。
- 正在请求。
- 用户取消。
- 请求成功。
- 请求失败。
- 回答格式异常但有原始文本。

## 七、开发者控制台命令

新增白名单命令：

| 命令 | 用途 |
| --- | --- |
| `llm status` | 输出是否启用、provider、model、是否有 key |
| `llm test` | 测试 endpoint 和鉴权 |
| `llm context` | 构建并输出脱敏后的上下文摘要 |
| `llm diagnose [question]` | 发起一次智能诊断 |
| `llm cancel` | 取消正在进行的请求 |

命令必须通过已注入 IPC 调用，不允许拼接 shell、JS 或动态 IPC channel。

## 八、任务拆解

1. 契约与 schema
   - 增加 IPC constants。
   - 增加 LLM config、diagnose payload、context options 的 schema。
   - 增加 IPC constants 单测。

2. 配置与安全存储
   - 增加 `llmConfig` 默认值和合并逻辑。
   - 增加 API Key 加密/掩码 helper。
   - 增加配置默认值和脱敏测试。

3. 主进程 LLM service
   - 实现 provider adapter。
   - 实现上下文构建、脱敏、裁剪。
   - 实现超时、取消、并发限制和错误码。
   - 增加 service 单测。

4. IPC 与 preload
   - 新建 `src/main/ipc/llm.ipc.js`。
   - 在 IPC index 注册。
   - preload 暴露最小方法。
   - 增加 IPC handler 测试和 smoke 风险验证。

5. renderer service 与 UI
   - 新建 `src/renderer/js/services/llm-client.js`。
   - 增加设置页配置区。
   - 增加诊断按钮、预览弹窗和结果展示。
   - 增加 renderer VM 测试。

6. 开发者控制台
   - 注册 `llm` 命令组。
   - 更新 `docs/developer-console.md` 或在本目录补充引用。
   - 增加命令解析/委派测试。

7. 文档与发布
   - 同步更新功能生命周期相关文档引用。
   - 补 release notes 草案。
   - 明确回滚和关闭方式。

## 九、最低验证命令

```bash
npm run verify
npm run test:smoke
```

涉及 UI 时，需要补手工验收记录；涉及打包或安全存储时，建议补：

```bash
npm run build:zip
```
