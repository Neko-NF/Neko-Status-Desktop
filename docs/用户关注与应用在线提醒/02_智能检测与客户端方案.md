# 02 — 智能检测与客户端方案

## 架构边界

首版新增 `native/presence-agent/` Rust Windows 程序，产物为：

```text
build/native/NekoPresenceAgent.exe
```

职责划分：

| 组件 | 职责 |
| --- | --- |
| Rust Agent | 前台应用智能检测、可选应用窗口快照、presence 发布、SSE/轮询事件接收、系统通知、独立托盘、DPAPI 凭据 |
| Electron 主进程 | 代理启动、配置同步、Agent Token enroll、命名管道 IPC、托盘租约、更新/退出协调 |
| Renderer | 关注动态页面、设置表单、关注/规则/隐私/拉黑可视化 |
| `neko-server` | 鉴权、关注关系、规则、可见性、presence 聚合、事件 Outbox、SSE |

Electron 不实现第二套检测，不直接跑 SSE，不在后台隐藏 Chromium 作为正式降级方案。

Activity 使用独立设备身份：

- 客户端保存 `activityDeviceId` / `activityDeviceName`，只用于关注动态。
- Agent Enroll 可以在没有完整状态上报设备密钥时创建活动专用设备绑定。
- 修改截图、完整状态上报、设备历史或主设备密钥，不应撤销 Activity Agent Token。
- 退出登录、修改服务器、关闭关注动态或删除活动设备时，才撤销活动凭据。

## Agent 使用的 Windows 能力

Agent 直接调用 Win32 或系统 API：

- `GetForegroundWindow`、`GetWindowThreadProcessId`：读取前台窗口所属进程。
- `GetLastInputInfo`：匿名输入节奏。
- `GetCursorPos`、`GetWindowRect`：判断鼠标是否在前台窗口内活动。
- GDI：显式授权时截取稳定上线应用窗口在桌面上的可见矩形，并压缩为小缩略图。
- WinHTTP：Bootstrap、快照上传、Presence、SSE、游标轮询、通知图片下载和系统代理/TLS。
- `Shell_NotifyIconW`：原生托盘。
- Windows Toast/AUMID：系统通知。
- Named Pipe、Mutex、DPAPI、Registry Run：本地协调、凭据保护、自启动。

禁止项：

- 不使用 PowerShell 常驻进程。
- 不使用键鼠 Hook。
- 不使用 WebView。
- 不截整屏，不采集未稳定或不匹配的窗口，不复用完整状态上报截图。
- 不提取应用图标。
- 不枚举后台进程列表。

## 稳定判定

Agent 每 500ms 采样一次，保留最近 10 秒滑动窗口。

满足任一条件即确认稳定：

| 路径 | 条件 | 用途 |
| --- | --- | --- |
| 交互快路径 | 同一进程连续前台至少 3 秒，并出现至少 3 次匿名输入脉冲或有效窗口内鼠标活动 | 普通切入应用 |
| 主导路径 | 连续前台至少 2 秒、最近 10 秒前台占比至少 70%，并有至少 3 次交互脉冲 | 轻微切换但明显以某应用为主 |
| 被动路径 | 连续前台至少 7 秒 | 阅读、视频、无频繁输入场景 |

补充规则：

- 窗口标题变化不算切换。
- 新候选未稳定前保留旧公开状态，避免频繁切换造成误报。
- 新候选即便稳定，也必须先通过服务端“公开应用”校验；未公开应用只进入本人的可管理列表，不对关注者可见。
- 10 秒没有有效候选进入 `idle`。
- 锁屏、休眠/恢复异常采样间隔、隐藏应用、暂停、退出会立即结束公开状态。
- Presence 心跳每 10 秒一次；服务端 30 秒无心跳判定离线。
- 网络重连采用带抖动的 1/2/5/10/30/60 秒退避。
- 网络恢复后只发布当前稳定状态，不回放本地原始采样。

## 采集与隐私边界

Agent 仅向服务端发送：

- 规范化进程标识。
- 展示名。
- 稳定开始时间。
- 设备。
- Agent 版本。
- 低粒度判定类型：`interactive`、`dominant`、`passive`、`idle` 等。
- 用户显式开启时，发送最大 640×360、512KiB 的前台应用窗口缩略图。

以下数据只存在内存中，不写日志、不落盘、不上传：

- 原始鼠标坐标序列。
- 原始输入节奏。
- 窗口标题。
- 键盘内容。
- 未开启活动快照时的任何截图。

活动快照额外约束：

- 稳定进入后再次核对前台进程，进程变化则不截图。
- 隐身模式的截图隐私规则优先；命中规则时不上传。
- 心跳不重复截图。
- 上传失败不阻塞 presence。
- 发布方原始快照不在 Agent 配置目录长期落盘。

## 性能目标

代理单独运行时目标：

- 空闲 RSS 95 分位不超过 20MiB。
- 活跃采样、SSE 和通知同时工作时 RSS 不超过 30MiB。
- 10 分钟平均 CPU 不超过单核 0.5%。
- Handle、线程数和内存连续运行 24 小时无持续增长。
- Presence 请求体不超过 2KiB，每 10 秒最多一次。
- 单个活动快照不超过 512KiB，只在稳定进入时尝试一次。
- SSE 复用单连接。

## Electron 集成点

新增主进程控制器：

```text
src/main/activity-agent-controller.js
src/main/ipc/activity.ipc.js
```

Renderer 侧：

```text
src/renderer/js/services/activity-client.js
src/renderer/js/pages/activity.page.js
```

Shared 契约：

```text
src/shared/ipc-contracts.js
src/shared/schemas.js
```

客户端启动时：

1. 读取本地 activity 配置。
2. 若功能开启，启动 Agent。
3. 如果需要凭据，调用 `POST /api/activity/agent/enroll`；若没有 `activityDeviceId`，服务端创建活动专用设备绑定。
4. 通过命名管道发送 `provision`。
5. 客户端接管托盘租约。
6. Renderer 显示代理状态。

配置体验要求：

- Renderer 开关采用“处理中/成功/失败恢复”三态反馈，弱网时禁用重复点击。
- 文案面向用户场景，不把“Agent、PID、协议版本、Token”作为主要表达。
- “我愿意公开的应用”支持读取当前前台进程名并填入，不读取窗口标题、不上传标题。
- 关注者侧规则编辑优先从“对方公开的应用”中选择；手填仅作为高级补充，服务端仍要校验对方已公开。

客户端退出时：

- 未开启独立后台：请求 Agent 本次退出。
- 已开启独立后台：释放托盘租约，Agent 继续运行并恢复独立托盘。
