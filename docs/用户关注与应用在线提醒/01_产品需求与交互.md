# 01 — 产品需求与交互

## 用户目标

用户可以关注其他用户，并为关注对象配置想看的应用。当被关注用户的任一授权设备稳定进入目标应用时，关注者收到系统通知，并可在客户端“关注动态”页面查看当前在线状态和最近事件。

这个能力用于“我想知道某位用户什么时候开始使用某个应用”，不是完整监控工具。因此首版把隐私、误报控制和低占用后台运行放在同等优先级。

## 首版范围

- Windows 客户端。
- `neko-server`。
- 实验性功能灰度。
- 单向关注，不逐条审批。
- 多设备按用户级合并：同一用户任一授权设备进入目标应用即视为该用户该应用在线。
- 同一用户同一应用只通知一次，后续设备加入只更新来源设备列表。

## 隐私模型

被关注者可见范围：

| 值 | 行为 |
| --- | --- |
| `private` | 关闭活动可见性，管理员也不可查看 |
| `admins` | 仅已关注的管理员可查看 |
| `followers` | 关注者与管理员可查看 |

默认值：

- `visibility=private`。
- 本机活动发布默认关闭。
- 上线提醒附带应用窗口快照默认关闭。
- 新检测到的应用默认不公开；用户明确公开后才会进入自己的公开应用目录。
- 用户可以停止公开某个应用，停止公开后服务端立即关闭该应用公开状态并撤销后续提醒。

用户可管理：

- 我关注的人。
- 关注我的人。
- 应用提醒规则。
- 我的可见范围。
- 我愿意公开的应用。
- 是否允许上线提醒附带应用窗口快照。
- 拉黑用户。

## 关注与规则

搜索：

- 支持模糊用户名。
- 支持精确 UID。
- 只返回 UID、用户名、头像。

关注：

- 用户 A 关注用户 B 后，A 可以为 B 添加应用规则。
- 关注关系单向；B 不需要审批，但 B 可以用隐私或拉黑限制可见性。
- 拉黑后，双方相关关注活动不可见，已有事件不再继续产生。

应用规则：

- 关注者可以从被关注用户的公开应用目录选择。
- 也可以手填规范化 `.exe` 进程名，但服务端必须校验该应用已经被对方公开，不能绕过公开目录。
- 服务端将进程名规范成小写、去路径、保留 `.exe` 后缀，例如 `Code.exe` → `code.exe`。
- `appKey` 首版使用 `win32:<process.exe>`。

发布方应用公开：

- 用户可以点击“从窗口选择应用”，客户端隐藏主窗口并复用隐私功能的框选层，只把选中窗口的进程名填入表单，不使用窗口标题作为展示名。
- 用户也可以手动输入规范化 `.exe` 进程名和可选展示名。
- Agent 检测到新应用时，只把它加入本人的“未公开”可管理列表；除非用户主动公开，否则关注者不可见、不可订阅、不会收到通知。
- 隐私范围只作用于“已公开应用”，不是对所有前台程序的全局授权。

## 通知语义

系统通知只在“稳定进入”时发送，离开只更新页面状态。

通知内容：

- 被关注者头像或默认图标。
- 应用名。
- 已在线秒数。
- 来源设备。
- 上线时间。
- 被关注者允许时显示稳定上线应用的窗口缩略图。

通知模板：

- 无图：头像、用户名、应用名、上线时间和来源设备，接近 Steam 好友上线提醒的轻量形式。
- 带图：头像作为 app logo，应用窗口缩略图作为 Hero image，正文仍保留时间和设备。
- 图片采集、上传、下载或 Toast 渲染失败时自动降级为无图模板，不能影响文字提醒。

冷却与过滤：

- 同一接收方、同一目标用户、同一应用 10 分钟内最多一次系统通知。
- 客户端或代理重启后先同步快照，不补发历史通知。
- 断线期间不超过 2 分钟的实时事件可以通知；更旧事件只进入事件列表。
- 系统通知遵守现有通知开关和 Windows 勿扰状态。

## 页面交互

实验性“关注动态”页面包含：

- 启用用户关注与应用提醒。
- 在此设备共享前台活动。
- 上线提醒附带应用窗口快照。
- 独立后台运行。
- Windows 登录时启动后台代理。
- 代理状态、版本、PID、内存、连接状态和最近心跳。
- 代理状态以用户语言展示：未开启、后台提醒中、网络重连中、已暂停、需要处理。版本、PID、协议号等技术信息只用于诊断，不作为主要文案。
- 修复 / 重新配置代理。
- 搜索用户、关注 / 取消关注。
- 规则添加、启用 / 禁用、删除。
- 隐私、公开应用、关注者和拉黑管理。

弱网与开关反馈：

- 用户点击开关后，界面先显示“正在保存”，并把对应开关置为处理中状态，避免重复点击。
- 服务端和 Agent 确认后再显示“已保存”。
- 若网络失败或 Agent 同步失败，界面自动恢复到上一次设置并给出可理解原因。
- 如果服务端快照偏好已保存但 Agent 同步失败，主进程发送补偿请求恢复服务端旧值。
- 页面不显示“假成功”；但也不让用户在网络差时误以为没有点击成功。

配置修改流程：

1. Renderer 进行 schema 校验后通过 IPC 提交。
2. Electron 主进程更新服务端或本地配置。
3. 必要时注册或撤销 Agent Token。
4. 主进程通过命名管道通知代理重载或刷新。
5. 页面等待代理确认后再显示成功，不做假成功状态。

## 需要打开客户端才能修改的内容

代理托盘只提供轻量运行控制，不提供配置编辑。以下操作必须打开客户端：

- 关注 / 取消关注。
- 添加或删除应用规则。
- 修改可见范围。
- 公开或停止公开应用。
- 拉黑 / 解除拉黑。
- 永久关闭后台模式。
- 退出登录。
- 修改服务器。
- 撤销授权或重新配置代理。

## 后续预留方向

首版接口为后续功能预留：

- 关注动态页扩展成事件时间线。
- 按分组管理关注对象。
- 规则增加时间段、状态条件、静默模式。
- 管理员审核视图。
- 事件聚合到通知中心。
- 与完整设备状态页做“只读跳转”，但不混用权限和采集逻辑。
