# 用户关注与应用在线提醒

本目录是“用户关注 + 前台应用在线提醒”功能的落地文档。当前已实现范围是 Windows 桌面端 + `neko-server`，入口仍放在实验性功能中，默认需要用户主动开启；Android 接收、管理与保活联调的后续方案见 09 文档。

## 当前结论

- 活动能力由独立 Rust 原生后台代理 `NekoPresenceAgent.exe` 执行，不由 Electron 客户端采集前台应用。
- Electron 客户端只负责配置、关注管理、隐私管理、可视化和代理生命周期编排。
- 活动设备身份使用独立的 `activityDeviceId` 和 Agent Token，不复用截图/完整状态上报的设备密钥；关闭或重置任一能力不应误伤另一能力。
- 应用公开采用“发布方主动允许”模型：新检测到的应用默认不公开，用户可以通过窗口框选选择要公开的应用，也可以手动输入规范化 `.exe` 进程名；关注者只能对发布方已经公开的应用设置提醒。
- 开启独立后台运行后，用户关闭 Electron 主窗口，代理仍可低占用地发布自己的活动并接收关注对象通知。
- 服务端通过 Agent Token 区分代理权限；Agent Token 只能写入 presence/活动快照、读取 bootstrap/events 和自己收到事件中的快照，不能搜索用户或修改关注、规则、隐私、拉黑。
- 实时提醒使用 SSE，SSE 不可用时代理使用游标轮询降级。
- 被关注者可通过默认关闭的全局开关允许“上线提醒附带应用窗口快照”；Agent 只截稳定上线时仍匹配的前台应用窗口矩形，失败自动降级为文字 Toast。
- 托盘始终只有一个所有者：客户端打开时显示合并托盘，客户端退出后由代理恢复独立托盘。

## 与既有能力的关系

该功能不是完整状态上报服务的替代品，也不接管既有整屏截图上报、OBS、推流、设备完整状态、更新下载或安装。它只处理：

- 本机前台目标应用的稳定在线状态；
- 关注对象活动事件的接收；
- Windows 系统通知；
- 被关注者显式授权后的短期应用窗口缩略图；
- 独立后台运行时的轻量托盘。

现有 `DeviceFav`、`StatusLog`、`AppUsageHistory` 不迁移、不复用、不改变语义。

实现上也必须避免“看起来耦合”：

- 页面文案不把关注动态称为截图上报、完整状态上报或设备状态服务的一部分。
- Activity Agent 的凭据、设备绑定、开关、托盘状态和撤销流程独立于既有整屏截图上传链路；活动快照使用独立接口、模型和私有目录。
- 合并托盘只是视觉和入口合并，不代表检测器、凭据或服务端 API 合并。

## 首版非目标

- 不做键鼠 Hook、截图识别、整屏采集、窗口标题上传、后台进程枚举。
- 不做逐条关注审批。
- 不展示被关注者完整历史会话，只展示当前状态和接收方自己的事件列表。
- 不在代理托盘里修改关注、规则、隐私或拉黑；这些操作必须打开客户端。

## 版本与开关

- 桌面端入口受实验性功能开关控制。
- 服务端总开关：`ACTIVITY_FOLLOW_ENABLED=true`。
- 默认隐私为 `private`，默认不发布本机活动。
- 活动窗口快照默认关闭。
- 独立后台运行需要用户显式开启；开启后“Windows 登录时启动代理”默认打开，但可单独关闭。
