# 04 — 联调测试发布回滚

## 本地验证

桌面端：

```powershell
npm run lint
npm test
npm run test:agent
cargo fmt --manifest-path native/presence-agent/Cargo.toml -- --check
cargo clippy --manifest-path native/presence-agent/Cargo.toml --all-targets --locked -- -D warnings
npm run build:agent
```

服务端：

```powershell
npx prisma generate
npx tsc --noEmit --pretty false
npx next build --webpack
npx prisma migrate deploy
```

说明：如果 Windows 上 Next/Turbopack worker 崩溃，可用 `next build --webpack` 做生产构建路径；这不改变运行时代码。

## Agent 单元测试范围

必须覆盖：

- 交互快路径。
- 主导路径。
- 被动路径。
- 频繁切换不误报。
- 窗口标题变化不算切换。
- 新候选未稳定时保留旧公开状态。
- 10 秒无候选进入 idle。
- 锁屏 / 恢复异常采样间隔立即 idle。
- WinHTTP URL 解析。
- 快照开关和截图隐私规则。
- 前台进程不匹配时不截图。
- 缩略图比例和 512KiB 上限。
- multipart 快照上传体。
- 带图/无图 Toast 构造与图片缓存清理。

## 生命周期验收

| 场景 | 预期 |
| --- | --- |
| 代理独立运行 | 只有一个原生托盘 |
| 打开客户端 | 代理托盘消失，客户端显示一个合并托盘 |
| 关闭客户端且后台模式开启 | 代理 2 秒内恢复托盘 |
| 客户端崩溃 | 代理继续检测、通知并恢复托盘 |
| 退出客户端，后台继续 | 不停止代理 |
| 退出全部（本次） | 停止客户端和代理，下次登录按设置恢复 |
| 永久关闭后台模式 | 撤销 Token、停止代理、删除启动项 |
| 代理托盘打开客户端 | 唤醒已有实例或启动 `NekoStatus.exe --page=activity` |

## 联调账号矩阵

联调前先阅读 [07_联调与开发踩坑记录.md](./07_联调与开发踩坑记录.md)。测试服务器固定为 `https://nekostatus.koirin.com`。

建议准备：

- 普通账号 A：关注者。
- 普通账号 B：被关注者。
- 管理员账号 C。
- B 的两台 Windows 设备。

覆盖：

- A 关注 B，B visibility=`followers`。
- B visibility=`private` 时 A 不可见。
- B visibility=`admins` 时只有已关注 B 的管理员 C 可见。
- B 拉黑 A 后，A 不再收到事件。
- B 的设备 1 / 设备 2 进入同一应用只生成一次用户级通知。
- B 隐藏应用后，在线状态结束且不再通知。
- A 删除规则后不再通知。

## 性能验收

代理单独运行：

- 空闲 RSS 95 分位 ≤ 20MiB。
- 活跃采样 + SSE + 通知 RSS ≤ 30MiB。
- 10 分钟平均 CPU ≤ 单核 0.5%。
- 24 小时 handle、线程数、内存无持续增长。
- Presence 请求体 ≤ 2KiB，每 10 秒最多一次。
- SSE 使用单连接。

## 用户体验验收

- 普通交互切入到通知不超过 6 秒。
- 被动场景不超过 10 秒。
- 少于 3 秒的切换不产生事件。
- Electron 完全退出后，目标用户活动仍能发布，关注者通知仍能接收。
- 主客户端关闭 30 分钟期间，Agent 内存和 CPU 符合目标。
- 系统通知遵守 Neko 通知开关和 Windows 勿扰状态。
- 客户端或代理重启先同步快照，不补发历史通知。
- 断线不超过 2 分钟的实时事件可以通知，更旧事件只进入事件列表。
- B 开启快照后，A 在 Electron 关闭、仅 Agent 后台运行时收到带头像、时间、设备和 Hero 图的 Toast。
- 快照采集、上传、下载或渲染失败时，文字 Toast 仍显示。
- B 关闭快照后，尚未下载的私有快照读取被拒绝，后续事件不再带图。

## 服务端快照权限验收

- 旧 Agent Token 缺少 `snapshot:write` 时上传拒绝，但 presence 正常。
- `shareSnapshots=false` 时上传拒绝。
- 隐藏应用上传拒绝。
- 非事件接收者读取返回 403。
- 事件接收者只能读取 payload 中绑定的快照。
- 24 小时过期后数据库记录和私有文件均被清理。

## 发布步骤

1. 完成文档、状态机和 Agent 协议。
2. 部署加法数据库迁移和默认关闭的服务端接口。
3. 重新生成 Prisma Client，并确认 enroll 已签发 `snapshot:write`。
4. 开启 `ACTIVITY_FOLLOW_ENABLED=true` 做受控联调。
5. 完成本地模拟及两个普通账号、一个管理员、两台目标设备联调。
6. 发布实验性桌面 Beta；后台模式和活动快照都必须用户主动开启。
7. 监控通知延迟、误报率、快照降级率、私有目录增长、Agent 崩溃、SSE 重连、CPU、内存和凭据错误。

## 回滚

服务端回滚首选：

1. 关闭 `ACTIVITY_FOLLOW_ENABLED`。
2. Agent 收到禁用响应后停止采集和网络连接。
3. 客户端隐藏或禁用入口。
4. 新增表和本地加密配置保留，便于后续恢复或排障。

桌面端回滚：

- 回滚客户端入口和 Agent 打包。
- 安装更新前使用 `shutdown(update)` 请求代理退出。
- 若用户已开启后台模式，新版本启动后应按新策略重新拉起或禁用代理。

不得把隐藏 Electron 进程作为正式降级方案。
