# 05 — 后台代理与托盘生命周期

## 代理状态

统一状态：

| 状态 | 含义 |
| --- | --- |
| `disabled` | 功能关闭，代理不运行 |
| `embedded` | 客户端已打开，代理运行但不显示独立托盘 |
| `background` | 客户端已退出，代理独立运行并显示托盘 |
| `paused` | 进程和托盘保留，但停止采集、发布和接收通知 |
| `update_shutdown` | 安装更新前有序退出，保留配置 |
| `session_exit` | 本次退出，下次 Windows 登录按设置恢复 |

规则：

- 功能开启时，无论是否开启独立后台，都由 Agent 执行检测。
- 未开启独立后台：客户端退出时 Agent 同步退出。
- 开启独立后台：客户端退出后 Agent 继续运行。
- 开启独立后台时，“Windows 登录时启动代理”默认开启，但可在客户端单独关闭。
- 托盘“临时暂停”不持久化，下一次登录恢复运行。
- 托盘“退出后台功能（本次）”保留开机启动设置，下次登录重新启动。
- 带图通知同样由 Agent 完成；Electron 退出不影响快照事件接收、私有图片下载和 Toast。
- 永久关闭后台模式、退出登录、修改服务器或撤销授权必须在客户端完成。

## 托盘合并

Agent 使用每用户唯一互斥锁保证单实例。客户端与 Agent 通过当前用户专属命名管道协商唯一托盘所有权。

Agent 独立托盘菜单：

- 当前状态：运行中 / 已暂停 / 网络重连中。
- 打开 Neko Status。
- 临时暂停 / 恢复。
- 退出后台功能（本次）。

客户端合并托盘菜单：

- 活动代理状态。
- 原有状态上报服务启动 / 停止。
- 打开 Neko Status。
- 临时暂停 / 恢复活动功能。
- 退出客户端，后台继续。
- 退出全部（本次）。

## 严格租约

托盘交接必须遵守：

1. 客户端接管前，Agent 先移除托盘并确认。
2. 客户端确认后创建合并托盘。
3. 客户端退出时先移除合并托盘，再通知 Agent 恢复。
4. 客户端崩溃或命名管道断开时，Agent 在 2 秒内恢复托盘。
5. 任意时刻不得出现两个托盘图标或两个检测器。

## 打开客户端

Agent 托盘打开客户端：

```text
NekoStatus.exe --page=activity
```

已有客户端实例时，通过现有单实例事件打开“关注动态”页面。

## 更新与卸载

自动更新前：

1. Electron 主进程发送 `shutdown(update)`。
2. 等待 Agent 进程退出。
3. 再交给 NSIS 覆盖安装。

安装/卸载兜底：

- NSIS 脚本调用 `NekoPresenceAgent.exe --shutdown-for-update`。
- 卸载时删除 HKCU Run 项。
- 是否删除用户配置继续遵守现有 `deleteAppDataOnUninstall: false`。

ZIP 手动覆盖前必须提示用户先选择“退出全部（本次）”，避免代理二进制被占用。

Agent 的通知图片缓存不参与托盘租约。缓存文件超过 48 小时由 Agent 清理；永久关闭功能时可由统一缓存清理入口删除。

## 状态恢复

| 用户动作 | 下次登录 |
| --- | --- |
| 临时暂停 | 恢复运行 |
| 退出后台功能（本次） | 若自启动开启则恢复运行 |
| 退出全部（本次） | 若自启动开启则恢复运行 |
| 永久关闭后台模式 | 不恢复，Token 撤销 |
| 退出登录 | 不恢复，Token 撤销 |
| 修改服务器 | 不恢复旧配置，需重新 Provision |
