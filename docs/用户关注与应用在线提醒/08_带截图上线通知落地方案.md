# 08 — 带截图上线通知落地方案

## 目标与现状

关注上线提醒由后台 `NekoPresenceAgent.exe` 完成。Electron 主窗口关闭后，只要用户开启独立后台运行，Agent 仍会接收 `activity.entered` 事件并显示 Windows 右下角 Toast。

本方案在现有文字通知上增加可选的“应用窗口快照”：

- 被关注者决定是否分享，默认关闭。
- 只截稳定上线时仍位于前台的目标应用窗口矩形，不截整屏。
- 只为公开应用上传，不读取或上传窗口标题。
- 截图、上传、下载、缓存或 Toast 渲染任一步失败，都降级为无图通知。
- 活动快照使用独立模型、接口、Token scope 和私有目录，不复用完整状态上报的截图链路。

## 端到端流程

1. 被关注者在“关注动态”页开启“在此设备共享前台活动”。
2. 被关注者主动公开某个应用，并将可见范围设为允许关注者查看。
3. 被关注者可选开启“上线提醒附带应用窗口快照”。
4. Agent 对前台应用完成 3/7 秒稳定判定。
5. Agent 再次校验当前前台进程仍与稳定应用匹配，并检查本地截图隐私规则。
6. Agent 截取窗口在桌面上的可见矩形，缩放并压缩为小 JPEG。
7. Agent 使用 `snapshot:write` 上传快照，得到 `snapshotId`。
8. Agent 继续发送不超过 2KiB 的 JSON presence，并可选携带 `snapshotId`。
9. 服务端创建用户级 session 和 `activity.entered` 事件，将快照元数据写入事件 payload。
10. 关注者 Agent 通过 SSE 或游标轮询收到事件，使用自己的 `events:read` Token 下载头像和快照。
11. Agent 将图片写入本地短期缓存并显示带图 Toast；图片不可用时显示文字 Toast。

心跳不会重复截图或上传。一次稳定进入最多准备一个快照；presence 重试复用同一个 `snapshotId`。

## 开关与隐私优先级

桌面端本地配置：

```json
{
  "enableActivityPublishing": true,
  "enableActivitySnapshots": false
}
```

服务端偏好：

```json
{
  "visibility": "followers",
  "shareSnapshots": false
}
```

生效条件必须同时满足：

1. Activity 功能已启用。
2. 当前设备允许发布前台活动。
3. `enableActivitySnapshots=true`。
4. 服务端 `shareSnapshots=true`。
5. 当前应用已公开，即 `ActivityAppCatalog.isHidden=false`。
6. 当前前台进程仍与稳定进入的进程一致。
7. 未命中隐身模式的截图隐私规则。

优先级从高到低：

```text
全局截图隐私阻止
> 进程隐私规则
> 应用未公开
> shareSnapshots 关闭
> Activity 快照开关
```

关闭分享后，服务端不再绑定新快照，并拒绝继续读取尚未下载的快照。已显示过的 Windows 通知无法远程撤回。

## Agent Profile

Electron 在 `provision` 和 `reload_config` 中同步：

```json
{
  "snapshotEnabled": true,
  "snapshotMaxBytes": 524288,
  "snapshotMaxWidth": 640,
  "snapshotMaxHeight": 360,
  "snapshotCacheDir": "C:\\...\\activity-snapshots",
  "snapshotPrivacyBlockAll": false,
  "snapshotBlockedProcesses": ["keepass.exe"]
}
```

Agent 状态增加 `snapshotEnabled`，用于页面诊断。Agent Token 仍由 DPAPI 当前用户范围保护。

## 采集与压缩

Windows 采集流程：

- `GetForegroundWindow` 获取当前前台窗口。
- `GetWindowThreadProcessId` 与 `QueryFullProcessImageNameW` 获取实际进程名。
- 进程名规范化后必须与稳定判定结果完全一致。
- `GetWindowRect` 获取窗口矩形。
- GDI `BitBlt` + `GetDIBits` 读取桌面上该矩形的可见像素。
- 保持宽高比缩放到最大 `640 × 360`。
- 依次尝试 JPEG 质量 82、74、66、58，结果必须不超过 512KiB。

首版有意采用“可见矩形”而不是 `PrintWindow`：

- 不尝试抓取被其他窗口遮挡的隐藏内容。
- 不截取其他显示器的整屏。
- 不读取窗口标题、控件文本或后台进程列表。
- 不在 Agent 配置目录永久保存发布方原始截图；编码结果直接上传。

## 服务端模型

`UserActivityPreference`：

```prisma
shareSnapshots Boolean @default(false)
```

`UserAppActivitySession`：

```prisma
snapshotId String?
```

`ActivitySnapshot` 记录：

- `userId`、`deviceId`、`sessionId`。
- `appKey`、MIME、私有相对路径。
- 宽、高、字节数、采集时间。
- `expiresAt`，首版保留 24 小时。

图片文件保存到服务端私有目录：

```text
activity-snapshots/<userId>/<deviceId>/<uuid>.jpg
```

该目录不能放在 Next `public/` 下。过期清理同时删除数据库记录和私有文件。

## API

### 隐私偏好

```http
GET /api/activity/me/privacy
PUT /api/activity/me/privacy
```

响应和更新支持：

```json
{
  "visibility": "followers",
  "shareSnapshots": true
}
```

桌面端保存失败时回滚本地配置；若服务端已保存但 Agent 同步失败，还要发送补偿请求恢复之前的 `shareSnapshots`。

### 上传快照

```http
POST /api/activity/snapshots
Authorization: Bearer <Agent Token>
Content-Type: multipart/form-data
```

scope：`snapshot:write`。

字段：

| 字段 | 说明 |
| --- | --- |
| `appKey` | 规范化 `win32:<process.exe>` |
| `capturedAt` | Unix 毫秒或 ISO 时间 |
| `width` / `height` | 缩略图尺寸 |
| `snapshot` | JPEG/PNG，最大 512KiB |

拒绝条件：

- Token 无 `snapshot:write`。
- `shareSnapshots=false`。
- 应用不存在或仍为隐藏。
- 文件不是 JPEG/PNG。
- 文件超过 512KiB。

### Presence 绑定

`POST /api/activity/presence` 仍为 JSON 且最大 2KiB：

```json
{
  "protocolVersion": 1,
  "state": "active",
  "appKey": "win32:code.exe",
  "snapshotId": "uuid"
}
```

服务端只接受同一用户、同一设备、同一应用、未过期且当前仍允许分享的快照。无效 `snapshotId` 被忽略，不影响文字 presence。

### 下载快照

```http
GET /api/activity/snapshots/:id
Authorization: Bearer <Agent Token>
```

scope：`events:read`。

只有事件接收者能读取，并且必须存在一条属于该接收者、指向同一 session、payload 中包含该快照 ID 的 `activity.entered` 事件。

## 事件 Payload

带图事件增加可选字段：

```json
{
  "snapshot": {
    "id": "uuid",
    "url": "/api/activity/snapshots/uuid",
    "mimeType": "image/jpeg",
    "width": 640,
    "height": 360,
    "sizeBytes": 84521,
    "capturedAt": "2026-06-22T08:00:00.000Z",
    "expiresAt": "2026-06-23T08:00:00.000Z"
  }
}
```

无图事件不包含 `snapshot`，旧 Agent 可继续按原格式处理。

## Windows Toast

无图模板：

- 标题：`<用户名> 正在使用 <应用名>`。
- 第一行：在线秒数和来源设备。
- 第二行：本地上线时间。
- 有可用头像时使用圆形 app logo，否则使用 Neko Status 默认图标。

带图模板：

- 头像作为 `appLogoOverride`。
- 应用窗口缩略图作为 Hero image。
- 正文仍保留应用名、在线秒数、来源设备和上线时间。
- 展示时长使用 Long。

头像只接受服务端同源 URL或受限大小的 JPEG/PNG data URL，避免通知事件引导 Agent 请求任意地址。快照下载必须携带 Agent Token。

## 本地缓存

接收方缓存目录：

```text
<snapshotCacheDir>/notification-images/
```

规则：

- 文件名由事件 ID 和用途构成，不使用服务端原始文件名。
- 只接受 JPEG/PNG 文件头。
- 单文件下载受 WinHTTP 2MiB 响应上限保护。
- 每次通知前清理超过 48 小时的缓存。
- 下载失败不重试轰炸，不影响事件游标推进。

## 降级矩阵

| 失败点 | 行为 |
| --- | --- |
| 前台进程已变化 | 不截图，正常发送文字 presence |
| 命中隐私规则 | 不截图 |
| GDI 采集失败 | 不截图 |
| 压缩仍超过上限 | 不上传 |
| 旧 Token 缺少 `snapshot:write` | 上传返回 401，下一次 provision 前均使用文字通知 |
| 上传失败 | presence 不带 `snapshotId` |
| 快照已过期或无权读取 | 文字 Toast |
| 头像失败 | 使用默认应用图标 |
| Hero 渲染失败 | Toast 调用失败不影响事件游标；后续事件仍可接收 |

Agent 对快照上传使用约 2.5 秒短超时，对单张通知图片下载使用约 3 秒短超时；超时立即进入上述无图降级路径。

## 验收清单

自动化：

- Rust：进程规范化、隐私规则、缩放比例、multipart、图片类型、缓存清理、陈旧事件过滤。
- Node：settings schema、默认关闭、保存回滚、服务端补偿、Agent profile 字段。
- Prisma：schema validate。
- 服务端：TypeScript、构建和迁移在服务器本机执行。

双账号手工联调：

1. A 关注 B，并为 B 的公开应用创建规则。
2. B 设为 `followers`，开启发布和快照。
3. B 将目标应用保持前台直到稳定。
4. A 关闭 Electron，只保留 Agent 后台。
5. A 收到带头像、Hero、时间和设备的 Windows Toast。
6. B 关闭快照后重新进入，A 只收到文字 Toast。
7. 模拟截图失败或删除图片文件，确认文字通知仍显示。
8. 验证超过 2 分钟旧事件、10 分钟冷却、隐藏应用、拉黑和删除规则均不通知。

## 发布顺序

1. 部署加法迁移和服务端代码，但保持 `ACTIVITY_FOLLOW_ENABLED` 受控。
2. 重新生成 Prisma Client。
3. 发布包含 `snapshot:write` 的 enroll。
4. 发布新版桌面端和 Agent。
5. 旧 Token 自动无图降级；用户下次 provision 后获得新 scope。
6. 观察上传拒绝率、图片平均体积、Toast 降级率、私有目录增长和过期清理。
