# 10 — 连接健康状态与服务端恢复清单

## 目的

本文固定桌面端 Activity 健康状态契约，并记录生产 `neko-server` 恢复后必须完成的服务端工作。旧目录 `_neko_server_build` 不是线上源码，不得从该目录构建或发布。

2026-07-14 的只读联调结果：

- Electron 与 `NekoPresenceAgent.exe` 进程持续存活，当前问题不是本地 pipe 重启风暴。
- 桌面 Bearer 请求 `/api/activity/*` 时先收到指向登录页的 `307`。
- 用有效 session 只读绕过中间件后，Activity 路由返回 Next `404 text/html`；对照接口 `/api/announcements` 返回正常 JSON。
- 因此客户端必须拒绝重定向、HTML 和错误 MIME；服务端必须同时修复中间件放行与 Activity 路由部署。

2026-07-15 的再次只读检查还发现：

- 公网 TLS 握手被 Windows Schannel 以 `SEC_E_CERT_EXPIRED` 拒绝，桌面端只能将其归类为不泄露底层细节的 `API_TRANSIENT`。
- 仅为诊断而跳过证书校验后，Apache 返回 `503 text/html`，说明证书和反向代理上游都需要先恢复；客户端不得把该 HTML 当作成功。
- 初次 Provision 遇到这类服务端故障时，UI 显示“服务器暂不可用”，保留本地开关和凭据状态，只提供手动立即检查，不把问题误报成用户设备需要重新配置。

## 健康快照 v2

`get_status`、Electron IPC 和 Renderer 使用同一份完整快照语义：

```text
schemaVersion = 2
revision / observedAtMs
settings / effectiveSettings
health.overall
health.lifecycle
health.localIpc
health.provision
health.receiver
health.publisher
```

状态轴不得互相覆盖：

- `lifecycle`：进程与运行方式，例如 `embedded`、`background`、`paused`。
- `localIpc`：Electron 与 Agent 的本地连接。
- `provision`：登录、设备和 Agent 凭据是否准备完成。
- `receiver`：SSE / polling 接收链路。
- `publisher`：本机活动发布链路。
- `overall`：由上述状态派生，不能反向写入子状态。

`publisher.currentApp` 只表示服务端在 Presence 响应中确认的公开应用。Agent
本机检测到的前台进程必须单独放在加法字段 `publisher.detectedApp`；当服务端
返回 `hidden / idle / offline` 时，`publisher.state` 为 `idle`、`currentApp`
必须清空。Renderer 可结合云端应用目录把 `detectedApp` 显示为“未公开”或
“正在确认”，不得写成“正在分享”。

旧 `state` / `connection` 只作为一个兼容周期的派生字段。Renderer 不再根据它们判断健康。

结构化错误只允许包含：

```json
{
  "code": "API_NOT_DEPLOYED",
  "message": "服务器暂未提供上线提醒",
  "httpStatus": 404,
  "transient": false,
  "atMs": 0
}
```

不得包含 Token、JWT、Cookie、响应正文、用户名或敏感完整路径。

## 客户端响应分类

| 场景 | 状态 | 自动恢复 |
| --- | --- | --- |
| 网络错误、超时、5xx | `retrying` | `1/2/5/10/30/60s` 加抖动 |
| 429 | `retrying` | 遵守 `Retry-After`，缺失时 60 秒 |
| SSE 连续失败但轮询成功 | `polling` | 保持降级可用，按退避探测 SSE |
| 401/403 | `credential_error` | 停止请求，等待重新 Provision |
| 307/308 登录跳转 | `unsupported` | 不跟随；5 分钟低频复查 |
| 404、HTML、错误 Content-Type/schema | `unsupported` | 5 分钟低频复查 |
| `ACTIVITY_FEATURE_DISABLED` 或 204 | `unsupported` | 15 分钟低频复查 |

用户手动“立即检查”、账号重新登录、服务器切换或配置 revision 更新可以打断等待；不能用高频循环替代。

## 桌面安装实例与设备映射

- 正式版和开发版各自在独立 userData 中生成一次 `activityInstallationId` UUID；它不是密钥，可以随 Enroll 发送，但服务端只落 SHA-256。
- `activityDeviceBindings` 只保存 `server + user + stable/dev` 对应的 Device ID/名称。退出登录或停用时清 Native Token、事件游标和当前标量绑定，保留这份非敏感映射，以便同用户重新登录时复用设备。
- Enroll 始终发送 `installationId + runtimeChannel`。开发版默认设备名带“（开发版）”，避免管理界面将两个通道误认为同一运行实例。
- 撤销请求必须是 `{ deviceId }` 或 `{ installationId, runtimeChannel }`，禁止发送会被 JSON 序列化为空对象的 `{ deviceId: undefined }`。
- Native Poll 的 `reset: true` 和 SSE 的 `activity.connection_reset` 仅推进并保存游标，不触发 Windows 通知；Renderer 仍使用健康快照 v2，不从控制事件派生连接健康。

## 服务端恢复实施清单

拿到真实 `Z:\NF\neko-server`、`E:\NF\neko-server` 或 SSH 后按以下顺序执行：

1. 更新公网证书与完整证书链，确认 Schannel、浏览器和无 `-k` 的公网烟测都能通过，再检查反代上游为何返回 Apache 503。
2. 记录当前分支、commit、`.next/BUILD_ID`、route manifest、7452 监听进程和公网反代配置。
3. 确认 Activity Prisma migration 已存在并已应用，重新生成 Prisma Client。
4. 确认完整 `/api/activity/*` 路由进入生产构建；不得只存在源码而缺少 route manifest。
5. 中间件把 `/api/activity` 交给各路由自身的 JWT / Agent Token 鉴权。这里的“放行”不是匿名访问。
6. 未知 `/api/*` 返回 JSON 404；API 未登录返回 JSON 401，禁止重定向网页登录页。
7. `ACTIVITY_FOLLOW_ENABLED=false` 返回 `503` 和 `ACTIVITY_FEATURE_DISABLED`，不能回落到 Next not-found 页面。
8. JSON 统一使用 `{ success, data, error: { code, message } }`，Content-Type 必须为 `application/json`。
9. SSE 必须返回 `200 text/event-stream`、`Cache-Control: no-cache`，每 15 秒真实 flush 注释心跳，支持 `Last-Event-ID`。
10. 反代关闭 SSE 缓冲，read timeout 至少 75 秒；确认公网客户端实际每 15 秒收到字节，而不只是源站产生了心跳。
11. Presence 接受 `active / heartbeat / hidden / idle / offline`，ISO 8601 时间和幂等 `clientEventId/sequence`；同一重试不得重复生成事件 ID。`sequence` 的 JSON number 仅允许安全整数，超出时使用 signed BIGINT 范围内的十进制字符串。迁移期只允许已认证且 `channel=legacy` 的旧凭据把安全整数 epoch-ms 适配为 ISO 后进入同一套时钟偏差/稳定时长校验；`stable/dev` 不得接受数字时间。移除该适配时必须提升 REST 协议版本，不能在同一 `protocolVersion` 内静默改变字段类型。
12. Enroll scope 固定包含 `presence:write,events:read,bootstrap:read,snapshot:write`。
13. 增加指标：Activity 路由状态码、错误码、活跃 SSE、断开原因、重连率、Presence 失败率、事件延迟。

## 公网验收

部署后必须对公网域名而不是只对 localhost 验证：

- 每个 Activity JSON 路由的状态码、Content-Type 和最小 schema。
- Bearer JWT 和 Agent Token 都不会被中间件重定向。
- 单个 SSE 连续稳定至少 10 分钟；心跳间隔符合约定，任意时刻每 Agent 只有一个消费连接。
- SSE 断开后能进入轮询，恢复后轮询停止且游标连续。
- 两个受控账号完成关注、规则、公开应用、Presence、事件和 Windows 通知闭环。
- 联调结束后清理临时账号、设备、Token、规则、事件、快照和私有文件。
